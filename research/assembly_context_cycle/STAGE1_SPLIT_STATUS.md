# Diagnostic split replay status

The native launch-boundary profile passed, but the registered internal `MFAssemble` replay is not complete. The production kernel combines projection derivatives, compact fragment writes, camera accumulation, and point accumulation in one launch, so CUDA events cannot separate those terms without a diagnostic implementation.

Final13682 has 28,987,644 observations; materializing the CD9 `gx[12]` and `gy[12]` arrays alone requires 5,565,627,648 bytes (5.183 GiB) in FP64. Compact `Gp` requires 3,130,665,552 bytes (2.916 GiB), with residual/radius intermediates, `Bo`, states, indices, and reference plus split accumulation outputs adding to the live set. A complete peak-live inventory and observed allocation failure are not yet available, so chunking is a conservative design choice rather than a demonstrated memory limit.

The preregistered implementation boundary is fixed at 1,000,000 observations per chunk, preserving global observation order. Each chunk must use the identical initial state, weights, and index mappings. Per-observation `Gp` and `Bo` require exact equality when the write expression and storage order are preserved. Accumulated `Hcc`, `Cdiag`, `bc`, `bp`, and `r2acc` require finite checks using the Euclidean norm: when `||reference|| > 0`, require `||split-reference|| / ||reference|| <= 1e-12`; when `||reference|| == 0`, require `||split-reference|| <= 1e-12`. Chunk setup and host transfers are excluded from kernel subphase event timings and reported separately.

No replay source or measurements passed review in this cycle. Consequently the internal phase breakdown, Stage 2 candidate selection, and its 5% microtime gate remain unmeasured. The native whole-kernel result cannot substitute for that gate, and no native optimization or Caspar comparison is opened.
